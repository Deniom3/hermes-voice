# Hermes Voice

**Голосовой ассистент для дома, который не уходит в облако.**

Вы говорите «Окей, Гермес» — колонка слышит, распознаёт фразу, отправляет её агенту Hermes,
озвучивает ответ и продолжает разговор. Распознавание и синтез речи работают локально,
ответы готовит ваш собственный агент: с доступом к дому, файлам, поиску и инструментам.

Колонка остаётся Яндекс Станцией: Алиса отвечает голосом, музыка и радио играют как раньше.
Меняется одно — кнопка паузы переходит к нашему контуру, потому что иначе на одно нажатие
работают два переключателя и пауза срабатывает со второго раза. Подробности — в
[docs/sendspin.md](docs/sendspin.md).

---

## Зачем это нужно

Готовые голосовые ассистенты хорошо отвечают на «включи музыку» и плохо — на «посмотри, что
в логах на сервере, и скажи, почему упал бэкап». Всё, что вы говорите, уходит в облако
провайдера, и вы не управляете ни моделями, ни памятью, ни тем, какие у ассистента есть права.

Hermes Voice решает это так:

- **речь не покидает дом** — распознавание и синтез идут на вашей машине;
- **ассистент — это агент, а не навык** — он умеет то, что умеют ваши инструменты: HA, SSH,
  поиск в вики, база знаний, скрипты;
- **колонка не превращается в кирпич** — штатная Алиса, музыка, будильники и радио остаются;
- **контур открытый** — вы видите каждый шаг: активацию, распознанный текст, ответ, тайминги.

## Что умеет

**Разговор**
- ключевое слово с локальным детектором (TFLite), порог настраивается;
- проверка ключа вторым проходом распознавания — меньше ложных срабатываний;
- Smart Turn: конец реплики определяется по смыслу, а не только по тишине;
- перебивание: можно заговорить во время ответа;
- «стоп» и кнопка обрывают ответ мгновенно;
- короткие реплики-заполнители, пока агент думает;
- окно продолжения: уточняющий вопрос без повторного ключевого слова.

**Дом**
- быстрые команды Home Assistant без обращения к модели: свет, розетки, климат, сцены;
- понимание падежей и разговорных названий устройств;
- показания датчиков голосом.

**Музыка**
- Music Assistant как источник: очередь, пауза, продолжение, переключение треков;
- пауза музыки на время ответа и возврат на том же месте;
- арбитраж: в один момент звучит ровно один источник — ответ, Алиса или музыка;
- кнопка на колонке управляет всем этим, в том числе длинным нажатием.

**Интерфейсы**
- веб-панель в браузере: микрофон, состояния, настройки, трансляция рабочего стола;
- MQTT и Home Assistant: состояние, громкость, команды;
- несколько колонок одновременно, каждая со своим именем и голосом.

## Как это выглядит

```
     ┌──────────────── Яндекс Станция ────────────────┐
     │  микрофон ──▶ voice-agent (Go) ──▶ кольцо, звук │
     └───────────────────────┬────────────────────────┘
                             │ WebSocket, PCM 16 кГц
                             ▼
     ┌──────────────── voice-hub (Python) ────────────┐
     │  детектор слова → проверка ключа → сбор фразы  │
     │  ASR → агент Hermes → TTS                      │
     └───────┬───────────────────────────┬────────────┘
             │ OpenAI-совместимый        │ WS
             ▼                           ▼
     ┌──────────────┐          ┌──────────────────────┐
     │ речевой шлюз │          │ Hermes Gateway :9119 │
     │ ASR + TTS    │          │ инструменты, память  │
     └──────────────┘          └──────────────────────┘
```

Хаб — единственная точка входа: он держит по одному WebSocket на клиента (колонка, панель),
внутри живёт речевой автомат. Тяжёлые модели вынесены на отдельную машину и доступны через
один HTTP-шлюз с интерфейсом, совместимым с OpenAI (`/v1/audio/transcriptions`,
`/v1/audio/speech`) — можно подставить faster-whisper, GigaAM, Silero, Piper, что угодно.

## Компоненты

| Компонент | Что делает | Где живёт | Порт |
|---|---|---|---|
| **voice-hub** | точка входа: WebSocket на клиента, речевой автомат, диалог с агентом | Linux-хост | 8796 |
| **voice-panel** | веб-панель: микрофон из браузера, состояния, трансляция стола | тот же хост | 8792 |
| **voice-agent** | микрофон, кольцевой буфер, воспроизведение, кольцо, музыка | Яндекс Станция (root) | — |
| **речевой шлюз** | распознавание и синтез за одним HTTP API | машина с моделями | 8000 |

## Системные требования

### Серверная часть

Хаб, панель и речевой шлюз — обычный Linux-хост с systemd. Модели распознавания и синтеза
живут отдельно: им нужен CPU или GPU, хабу — нет.

| | Минимум | Проверено на |
|---|---|---|
| ОС | Linux с systemd | Ubuntu 24.04 LTS, ядро 6.8 |
| Python | 3.10+ | 3.14.7 в venv; CI — 3.12 |
| Процессор | 1 ядро | 8 vCPU, хабу хватает одного |
| Память | 512 МБ на хаб | 5 ГБ на хосте; `voice-hub` занимает ~150 МБ |
| Диск | 1 ГБ под код и кэш | 48 ГБ; кэш ответов ограничен 50 МБ |
| Порты | 8796 (хаб), 8792 (панель) | те же |

Зависимости — `requirements.txt`: numpy, aiohttp, websockets, onnxruntime, paho-mqtt.
Для сборки агента под колонку нужен Go 1.22+.

Если включено кольцо ключевого слова, оно пишет около 115 МБ в час на колонку и
ротируется по `keep_s` — место на диске считается с этим запасом.

### Колонки

Проверено на двух, обе с root и SSH (dropbear на порту 2222):

| Колонка | Платформа | Ядро | Память | Сборка |
|---|---|---|---|---|
| Станция Микро (в конфиге `lite-1`, спальня) | Station Micro v1.2 | 4.9.68 | 238 МБ | Buildroot 2020.02.1 |
| Станция Лайт 2 без часов (`lite-2`, кухня) | Prune EVT2 | 4.9.113 | 237 МБ | Buildroot 2020.02.1 |

Агент собирается под 32-битный ARM (`GOOS=linux GOARCH=arm GOARM=7`) и работает на
64-битном ядре обеих колонок. Различия платформ — светодиоды, звук и способ снятия
микрофона — учтены флагом `-platform`.

### Что ещё нужно

- **Речевой шлюз**: ASR и TTS за одним HTTP API, совместимым с OpenAI
  (`/v1/audio/transcriptions`, `/v1/audio/speech`).
- **Агент Hermes**: WebSocket-эндпоинт (`:9119/api/ws`).
- **Опционально**: Home Assistant для быстрого дома, MQTT для сущностей и озвучки из
  автоматизаций, Music Assistant для музыки. Без них работают разговор, распознавание,
  синтез и ответы агента.

### Чего ждать не стоит

- **установки в один клик** — нужен root на колонке и своя машина под модели;
- **поддержки всех колонок Яндекса** — проверены две модели из таблицы выше;
- **готовых моделей в репозитории** — ASR и TTS подключаются снаружи.

## Быстрый старт

```bash
git clone https://github.com/<owner>/hermes-voice.git
cd hermes-voice

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp hub/config.example.json /etc/hermes-voice/hub.json   # адреса шлюза, агента, HA, MA
$EDITOR /etc/hermes-voice/hub.json
```

Без root для отладки: `export HUB_CONFIG=$PWD/hub/config.example.json`.

Панель (нужен Node 18+):

```bash
cd panel/frontend && npm ci && npm run build && cd ../..
python3 panel/server.py
```

Хаб для отладки без systemd:

```bash
.venv/bin/python hub/voice_hub.py --port 8796 --out /tmp/station-hub
curl -s http://127.0.0.1:8796/health
```

Агент на колонке (Go 1.21+):

```bash
cd agent
GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0 \
  go build -trimpath -ldflags="-s -w" -o voice-agent .
```

Установка на колонку и автозапуск — в [agent/README.md](agent/README.md) и
[docs/deploy.md](docs/deploy.md).

## Конфигурация

Один файл — `hub.json`: по умолчанию `/etc/hermes-voice/hub.json`, путь
переопределяется `HUB_CONFIG`. Адреса в коде и примере — плейсхолдеры
`<hub-host>`, `<speech-host>`, `<station-host>`.

```json
{
  "hermes":    { "url": "ws://<hub-host>:9119/api/ws" },
  "asr":       { "url": "http://<speech-host>:8000/v1/audio/transcriptions", "model": "gigaam-asr" },
  "tts":       { "url": "http://<speech-host>:8000/v1/audio/speech", "voice": "eugene" },
  "mqtt":      { "host": "<mqtt-host>", "port": 1883, "user": "mqtt", "prefix": "hermes/stations" },
  "sendspin":  { "url": "ws://<ma-host>:8927/sendspin", "output": "default" },
  "wake":      { "model": "/srv/kws/models/...", "stations": { "lite-1": { "mac": "aa:bb:...", "area": "spalnia" } } },
  "dialog":    { "silence_ms": 900, "hard_silence_ms": 3500 }
}
```

| Ключ в `hub.json` | Смысл |
|---|---|
| `hermes.url` | WebSocket агента Hermes |
| `asr.url`, `asr.model` | распознавание (`/v1/audio/transcriptions`) |
| `tts.url`, `tts.voice`, `tts.volume` | синтез (`/v1/audio/speech`) |
| `mqtt.*` | брокер, префикс топиков и discovery |
| `sendspin.url`, `sendspin.output` | Music Assistant и устройство вывода |
| `wake.*` | модель ключевого слова, пороги и привязки станций |
| `dialog.*` | пороги конца реплики и окно диалога |
| `replies.*`, `phrases.*` | произносимые тексты и группы слов маршрута |

**Переопределение из окружения.** Любой ключ файла можно переопределить
переменной `HUB_<ПУТЬ>`: `mqtt.prefix` → `HUB_MQTT_PREFIX`. Пустое значение
считается «не задано». Удобно для отладки, но источник истины — файл.

**Что живёт только в окружении** (секреты в `hub.json` не пишем):

| Переменная | Где | Смысл |
|---|---|---|
| `HUB_CONFIG` | хаб | путь к файлу конфига |
| `HASS_URL`, `HASS_TOKEN` | хаб | Home Assistant; без них быстрый дом выключен |
| `MQTT_PASSWORD` | хаб | пароль брокера |
| `HERMES_DASH_TOKEN_FILE` | хаб | файл с токеном агента |
| `MA_MCP_BIN` | хаб | путь к `music-assistant-mcp` |
| `VOICE_PORT`, `VOICE_HUB_URL` | панель | порт панели и адрес хаба |

`ASR_URL` и `TTS_URL` ещё читаются, но только как запасной путь: значение из
`hub.json` приоритетнее. `VOICE_SILENCE_MS`, `VOICE_HARD_SILENCE_MS` и
`SMART_TURN_THRESHOLD` больше не используются — эти пороги в `dialog.*`.

Полный пример — `hub/config.example.json`, развёртывание — [docs/deploy.md](docs/deploy.md).

## Управление

```bash
systemctl status voice-panel voice-hub
systemctl restart voice-hub
journalctl -u voice-hub -f                 # активация, фраза, ответ, тайминги
curl -s http://127.0.0.1:8796/health       # кто подключён и в каком состоянии
```

Колонка:

```bash
ssh -p 2222 root@<station-host>
/etc/init.d/S99zhermes restart
tail -f /tmp/hermes-agent.log
```
