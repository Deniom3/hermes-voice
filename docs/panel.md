# Локальная голосовая панель Hermes

Живой разговор голосом с агентом Hermes: орб реагирует на речь, распознавание и синтез идут
локально, ответ звучит голосом и печатается в панели. Собрано на компонентах Pithagoras (Apache 2.0).

**Текущая (основная) реализация — эта ветка `main`: панель — клиент голосового хаба.**
Прежняя самописная реализация (панель сама ходила на 139 своим HTTP-протоколом, VAD в
браузере) удалена; при необходимости её можно достать из истории git.

Контур текущей реализации:

```
Браузер ──WS /voice-ws──▶ :8792 (server.py) ──WS клиент──▶ хаб :8796
   ▲                                  ▲                        │
   └──────── события, звук ───────────┘                        │
                                                    ядро SpeechCore:
                                                    ключ, конец фразы, окно,
                                                    агент :9119,
                                                    ASR и TTS — шлюз <speech-host>:8000
```

Панель больше не держит своё речевое ядро: она переводит протокол браузера в протокол хаба
(бинарный PCM вверх, состояния и звук вниз) и остаётся тонким транспортом. Колонка ходит в
тот же хаб напрямую. Поэтому ключевое слово, конец фразы, окно диалога, распознавание, агент
и синтез для панели и колонки — один и тот же код.

Отличия панели от колонки задаёт роль в `hello`:

| | `role: station` | `role: panel` |
|---|---|---|
| команды устройству (led/sound/pause) | да | нет |
| цвет по событиям агента (`tool`) | да, кольцо | да, орб |
| сбор датасета KWS | да | нет |
| старт без ключевого слова | нет | да, `{"t":"start"}` |
| проверка обращения по тексту | да | нет (`origin=button`) |

Wyoming-мосты удалены из репозитория: панель работает через хаб, а быстрый дом — через REST
и реестры Home Assistant. Если понадобится отдавать наши модели внутрь HA Assist, файлы
берутся из истории git.

## Фразы-заполнители

Живут в библиотеке реплик (`hub/replies.py`), поэтому одинаково работают и в панели, и на
колонке: пока агент не выдал первый звук ответа, играется короткая готовая фраза
(«секунду, думаю»). Записи лежат wav-файлами в `hub/replies/eugene/`, ничего не
синтезируется в момент паузы. Тот же механизм кэширует постоянные короткие ответы
маршрута — «Включил», «Комната не задана…»: первый синтез сохраняется, дальше звучит
сразу с диска.

**По умолчанию выключено.** Включается `VOICE_FILLERS=1` для `voice-hub`. Тайминги — в
`hub.json → fillers`: `first_s` (первая фраза, 6 с), `min_gap_s`/`max_gap_s` (7–15 с),
`max_count` (40 фраз — страховка от бесконечной задачи). Первый звук ответа гасит
заполнители сразу.

## Фразы-заготовки: как пересобрать

Наборы фраз лежат в манифесте `hub/replies/<голос>/manifest.json` (пул `think` — восемь
фраз). Готовые записи хранятся файлами рядом и играются прямо с диска — мгновенно и без
зависимости от того, поднят ли синтез.
`hub/replies/<голос>/index.json` — расшифровка: какая фраза в каком файле и сколько звучит.

Пересобрать после правки манифеста (или смены голоса):
```bash
.venv-wake/bin/python scripts/make-replies.py          # только отсутствующие
.venv-wake/bin/python scripts/make-replies.py --force  # перезаписать все
```
Порядок поиска записи: библиотека в проекте → кэш синтеза
(`/root/.hermes/voice-cache/replies`). Запасного синтеза «по требованию» у заполнителей
нет намеренно: в паузе ждать синтез нельзя.

## Громкость ответов

В углу сцены — кнопка-динамик: открывает дорожку 0–100%, значение
запоминается в браузере (localStorage), при нуле иконка становится перечёркнутой.
Регулятор включён в цепочку **после** анализатора громкости (того, что рисует орб), поэтому
шкала орба показывает саму речь, а не выставленную громкость.

Питфол: `Number(localStorage.getItem(...))` для отсутствующего ключа даёт **0**, а не `NaN` —
из-за этого панель стартовала с нулевой громкостью (нашлось замером). Проверять `null` явно.

## Режимы экрана в окне живого браузера

- **браузер** (по умолчанию) — Chrome во весь экран: в окне панели видно только браузер;
- **стол** — Chrome сворачивается, видно рабочий стол.

Переключатель — в шапке окна «Живой браузер». Работает через CDP (`VOICE_CDP_URL`, по умолчанию
`http://127.0.0.1:9223`): Chrome не переключает состояние напрямую, поэтому сервер сначала возвращает
обычное окно, затем ставит нужное (из полного экрана нельзя свернуть, из свёрнутого — развернуть).

Чтобы работа агента была видна в панели, у агента должен быть прописан тот же браузер:
`hermes config set browser.cdp_url http://127.0.0.1:9223` (правится только человеком).

## Индикация состояний

Цвет орба повторяет кольцо колонки, чтобы одинаковые состояния выглядели одинаково на двух
интерфейсах. Палитра `hermes` — палитра по умолчанию (`panel/frontend/src/orb-style.ts`):

| Режим | Когда | Цвет |
|---|---|---|
| `idle` | микрофон выключен, ждём нажатия | `#55707a` серо-бирюзовый |
| `input` | слушаю | `#0fffc3` бирюза |
| `thinking` | жду ответа агента | `#ffaf0f` янтарь |
| `tool` | агент выполняет инструмент | `#87ff0f` лайм |
| `output` | говорю | `#0fffc3` бирюза |
| `muted` | микрофон отключён вручную | `#6d7783` серый |

`idle` намеренно уведён в серо-бирюзовый: раньше он был тёмной бирюзой и по цвету нельзя
было отличить «не слушаю» от «слушаю».

`tool` приходит событием от агента (`tool.start` / `tool.complete`) — тем же, что переключает
кольцо колонки. В панели при `tool.start` включается режим `tool` и под орбом появляется
«выполняю: <имя>», при `tool.complete` — возврат в `thinking`.

**Известное ограничение:** быстрый инструмент (например, `terminal` за 50 мс) успевает
завершиться между двумя кадрами, поэтому лайм визуально не виден — орб выглядит так, будто
сразу перешёл из «думаю» в «говорю». Если такие инструменты нужно показывать заметно,
лечится минимальной длительностью индикации, а не другим цветом.

## Что внутри

- **`panel/server.py`** — WS-сервер на 8792 и тонкий транспорт: держит `/voice-ws` для браузера,
  переводит его в протокол хаба (`VOICE_HUB_URL`), отдаёт собранную страницу и `/health`,
  проксирует VNC и переключает режимы экрана через CDP. Речевого ядра, распознавания и
  синтеза здесь нет.
- **`panel/frontend/src/`** — фронтенд (React + Vite): орб (`VoiceOrb.tsx`), сцена с окнами, микрофон,
  VAD в браузере (сегментация реплики перед отправкой), планировщик озвучки (`App.tsx`).
- **`panel/frontend/public/voice-assets/`** — локальная модель VAD (Silero v5 + legacy, ONNX-сборка wasm, ~15 МБ).
  Нужна, чтобы сегментация не тянула ничего из интернета.
- **`scripts/`** — смежные скрипты озвучки: `make-fillers.py` (нарезка
  фраз-заполнителей), `scripts/station-tts.sh` (Яндекс.Станция через сервис tts-station);
  `scripts/recolor_led.py` — перекраска LED-паттернов колонки с сохранением движения.
  Прежний `panel/supertonic-tts.sh` (удалён) удалён: синтез идёт через шлюз <speech-host>:8000, а скрипт
  дёргал `:8010` напрямую и никем не вызывался.

## Запуск

```bash
cd panel/frontend
npm ci
npm run build
systemctl restart voice-panel      # юнит лежит в panel/deploy/voice-panel.service
```

Сервер слушает `:8792`, страница отдаётся из `dist/`. Проверка: `curl -s localhost:8792/health`.

## Настройки

Все через переменные окружения (`/opt/hermes-voice/.env` (юнит читает его через EnvironmentFile), шаблон — `.env.example`):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `VOICE_PORT` | 8792 | порт панели |
| `VOICE_HUB_URL` | ws://127.0.0.1:8796/ws | хаб, к которому подключается панель |
| `VOICE_CDP_URL` | http://127.0.0.1:9223 | Chrome для режимов экрана |
| `VOICE_VNC_HTTP` / `VOICE_VNC_WS` | http://127.0.0.1:6080 / ws://127.0.0.1:6080/websockify | трансляция рабочего стола |

Распознавание, синтез, модель агента, ключевое слово и тайминги живут в хабе — это его
переменные, см. [deploy.md](deploy.md). Панель их не читает: у неё один голосовой тракт,
полученный по WS.

## Что удалено вместе с легаси

Раньше панель держала свой речевой путь и проверяла релевантность реплики отдельным
арбитром (`relevance_gate.py`, переменные `RELEVANCE_*`). После перевода на ядро хаба это
не работает; файл удалён, настройки не читаются. Постороннюю речь теперь отсекает окно
диалога и проверка обращения в ядре, а не арбитр в панели.

## Грабли, которые уже пройдены

- **Пауза после «окей, гермес» больше не ломает разговор.** Клиент режет реплику по паузе и сразу
  шлёт новый `start`; распознавание не успевает дать текст (нужно ≥1.3 с накопления), и раньше
  услышанное слово умирало вместе с закрытой сессией — человек говорил заново. Теперь слово
  переносится в новую реплику (окно диалога открывается, имя не спрашивается), а если текста нет
  вовсе, но балл уверенный — активация всё равно считается состоявшейся. Проверка на реальных
  записях: клип «окей, гермес» + пауза + «сколько времени сейчас в Москве» без имени → ход пошёл,
  ответ получен (проверялось стендом `panel_wake_carry_probe.py` из лаборатории voice-gate-lab,
  удалённой 2026-10-13).
- **Куски планируются встык** по часам `AudioContext`, а не «ждём `onended`» — иначе пауза на стыке
  равна времени декодирования.
- **Цикл проигрывания живёт, пока играет хоть один кусок**: аудио приходит уже во время речи, и выход
  на пустой очереди терял остаток ответа.
- **Один анализатор и одна петля кадров** на всю озвучку (анализатор на кусок затирал уровень нулём).
- **Анимация говорения привязана к звуку, а не к режиму**: режим сбивают эхо и служебные события, из-за
  этого фиолетовое состояние пропадало посреди ответа.
- **Громкость речи доходит лишь до ~0.16 из 1.0** — без растягивающей кривой облачко почти не двигалось.
- **Перебивание**: ход помечается номером, хвост отменённого ответа отбрасывается; новая реплика
  обязана отменять прошлую задачу ответа (иначе две корутины читают шлюз).
- **Сессия распознавания обязана закрываться** (новая реплика закрывает прежнюю; брошенная закрывается
  сама через 20 с) — иначе наш сервер долбит 139 пустыми пересчётами и грузит её на все ядра.

Подробности и замеры — в скилле `local-voice-agent-audio-stack`.
