# Sendspin и музыка Music Assistant

Колонка играет музыку из Music Assistant (MA) как локальный плеер Sendspin.
Отдельного бинаря нет: клиент живёт в том же процессе `voice-agent`, что и
голосовой агент, TTS и нативный `maind`.

```
аудио:     MA ──Sendspin/WebSocket──> voice-agent ──aplay──> ALSA/dmix
управление: голос ──> хаб :8796 ──MCP/JSON-RPC──> MA
```

Аудио идёт напрямую от MA к колонке. Хаб не проксирует PCM: это ломало бы
синхронизацию и грузило бы его круглосуточным потоком. Хаб управляет только
очередью и состоянием.

## Настройки на хабе

Единственный источник конфигурации — `/etc/hermes-voice/hub.json`. На колонке
нет ни `agent.env`, ни `SENDSPIN_*` в init-скрипте.

```json
{
  "sendspin": {
    "url": "ws://192.168.1.10:8927/sendspin",
    "output": "default"
  },
  "wake": {
    "stations": {
      "lite-1": {
        "sendspin": {
          "name": "Комната (Hermes)",
          "state_dir": "/data/opt/hermes-station/sendspin"
        }
      },
      "lite-2": {
        "sendspin": {
          "name": "Кухня (Hermes)",
          "state_dir": "/data/opt/hermes-agent/sendspin"
        }
      }
    }
  }
}
```

- `sendspin.url` — WebSocket MA; без него клиент не запускается.
- `sendspin.output` — ALSA-устройство для `aplay`, обычно `default`.
- `wake.stations.<имя>.sendspin` перекрывает общие значения.
- `enabled: false` на любом уровне выключает плеер для станции.
- `state_dir` хранит `identity.key`; при перезагрузке это тот же `client_id`.
  Каталог должен быть записываемым, ключ — с правами `0600`.

После `hello_ok` хаб отправляет агенту сообщение:

```json
{"t":"sendspin","config":{"url":"ws://…","name":"Кухня (Hermes)",
 "state_dir":"/data/opt/hermes-agent/sendspin","output":"default"}}
```

Агент запускает клиента только после этого сообщения. Повторные конфиги
игнорируются: на процесс один клиент.

## Управление из MA

На хосте хаба нужны URL и токен MA. Они лежат в
`/etc/hermes-voice/ha.env` (файл читает systemd-юнит `voice-hub`):

```sh
MUSIC_ASSISTANT_URL=http://192.168.1.10:8095
MUSIC_ASSISTANT_TOKEN=…
```

`hub/ma_control.py` запускает `/root/.local/bin/music-assistant-mcp` как
дочерний процесс и говорит с ним JSON-RPC по stdio. Это не тянет зависимости
MA в venv хаба. Используются инструменты `ma_list_players`, `ma_queue`,
`ma_playback`.

Голосовые команды разбираются до LLM:

| Фраза | Действие |
|---|---|
| `стоп`, `выключи музыку` | `ma_playback stop` + локальный `stop` агенту |
| `пауза` | `ma_playback pause` |
| `продолжить`, `играй` | `ma_playback play` |
| `дальше`, `следующий трек` | `ma_playback next` |
| `назад`, `предыдущий трек` | `ma_playback previous` |
| `перемотай на N секунд/минут`, `в начало` | `ma_playback play` + `seek_seconds` |
| `что играет` | `ma_queue` → короткий ответ через TTS |

«Стоп» из голоса и кнопки останавливает очередь MA, а не только локальный
`aplay`. Кнопка паузы дополнительно вызывает `sendspinPause()`.

## Пауза под голос

При активации ключевого слова хаб делает два действия:

1. `cmd pause` агенту — останавливает локальный `aplay` **и нативный плеер**
   (Алису), если тот реально играет; возвращает `was_playing` и
   `sendspin: true/false`;
2. `ma_control.pause_if_playing()` — ставит на паузу очередь MA, если играет
   именно наш плеер `<станция> (Hermes)`.

Натив гасится отдельно от Sendspin. Раньше при `sendspinEngaged()` команда
делала `return`, не трогая нативный плеер: `engaged` включает `localPaused`,
который остаётся true и после нашей же паузы, поэтому Алиса играла поверх
ответа. `mediaState()` проверяет факт, а в простое `pause` не отправляется —
на Лайт 1 этот метод поднимает последнее радио.

Хаб запоминает `_ma_paused` и `_agent_sendspin`. Если играл натив, а не
Sendspin, в автомате выставляется `alice = paused` и `owner = alice` — тогда
кнопка во время ответа знает, что возвращать. После ответа, когда музыка
должна вернуться:

1. `ma_control.resume_if_paused()` — снимает паузу с очереди MA;
2. `cmd play` агенту — только если агент сам ставил паузу Sendspin.

Если агент паузу Sendspin не ставил (например, MA играл, а `aplay` ещё не
поднялся), после `resume` MA сам пришлёт `stream/start`; отдельная команда
`play` агенту не отправляется. Иначе она поднимает последний нативный источник
Алисы — радио вместо трека MA.

Для TTS без активации (`say`/`sound`) агент по-прежнему использует локальный
оверлей: `sendspinPause()` и `sendspinResume()` с общим refcount. Это не
останавливает очередь MA, но на время короткой озвучки звук не накладывается.

## Громкость

MA присылает громкость 0–100 в `server/command` (`player.command=volume`).
Агент пишет этот процент прямо в ALSA `Master` (`amixer sset`), поэтому
ползунок MA меняет реальную громкость динамика. Нативный VolumeSet на части
прошивок квантует и не даёт точный процент; если прямой ALSA-путь недоступен,
остаётся программное масштабирование PCM.

Первый `client/state` отправляет фактический процент ALSA, а не дефолтные
100. Когда громкость меняют кнопкой или Алисой, `watchVolume` сообщает хабу
событие `volume`; хаб вызывает `ma_control.set_volume()` → `ma_volume`, и MA
показывает новый уровень. Повторный вызов с тем же `volume_level` отбрасывается,
поэтому ответ MA на нашу же команду не зацикливает синхронизацию. Mute —
программное обнуление PCM; громкость колонки при этом не теряется.

## Наложение источников и автомат

Решает не набор флагов, а автомат `hub/sources.py`: три состояния, владелец и
причина паузы.

```
alice  playing | paused | idle    нативный плеер (mediad)
ma     playing | paused | idle    очередь Music Assistant
agent  streaming | paused | idle  наш Sendspin/aplay (транспорт MA)
owner        alice | ma | none
pause_reason hub | button | overlap | app
```

События: `wake`, `response_end`, `button`, `switch_source`, `alice_started`,
`ma_started`, `stop`, `poll`. Функция `decide()` чистая: она не делает I/O, а
возвращает список действий, которые исполняет хаб.

Инвариант — **ровно один владелец**. Второй источник гасится один раз на
переходе состояния, а не по таймеру каждые полсекунды. Поэтому циклов
«глушу оба» и повторных обрываний нет.

`_overlap_watch` раз в 0.5 с опрашивает `state` агента и передаёт факты
(`native_playing`, `sendspin_playing`, `sendspin_engaged`) в автомат.
Важно: `spin` — это наш `aplay`, а не «MA играет». После паузы буфер ещё
доигрывает, поэтому MA помечается играющим только на фронте потока, иначе
watchdog снова видел бы конфликт.

## Кнопка

Короткое нажатие (< 700 мс) — пауза. Длинное (≥ 700 мс) — переключение
источника. Длительность считается в `agent/alice_key.go` между `value=1` и
`value=0` (автоповторов прошивка не шлёт), метка живёт вне цикла чтения.
Агент отправляет `{"t":"interrupt","long":true}`.

**Кнопка целиком наша.** Агент забирает evdev через `EVIOCGRAB`, поэтому
`maind` нажатие не видит вовсе. Это не роскошь, а необходимость: пока он
видел кнопку, на одно нажатие работали два независимых переключателя —
наш и штатный. `maind` после нашей паузы возвращал звук через 0.6 с
(`switchUserState` → play), и пауза требовала второго нажатия:

```
23:07:57.867  interrupt отправлен
23:07:58.130  музыка: false (pause)          ← пауза встала
23:07:58.731  музыка: true (switchUserState) ← maind вернул звук
```

Цена решения: если агент не запущен, кнопка на колонке не работает вообще
(штатная Алиса голосом работает всегда). Watchdog поднимает агента через
`S99zhermes`.

| Жест | Состояние | Действие |
|---|---|---|
| короткое | что-либо звучит (Алиса, MA, наш ответ) | пауза всего: натив + MA + наш поток |
| короткое | идёт наш ответ | оборвать речь, музыка не поднимается |
| короткое | тишина, владелец MA, очередь не пуста | продолжение MA |
| короткое | тишина, владелец Алиса | включить Алису (`native_play`) |
| короткое | тишина, владелец неизвестен | включить Алису |
| длинное | играет Алиса, очередь MA не пуста | пауза Алисы, играет MA |
| длинное | играет MA | пауза MA, играет Алиса |
| длинное | тишина | включить Алису |
| любое | хаб недоступен | локальный play/pause натива (`hubOnline`) |

Владелец (`owner`) — это «чей сейчас режим», а не «кто физически звучит»:
он запоминается при паузе и определяет, что вернёт следующее нажатие.
После «стоп» и обрыва ответа владелец сохраняется, чтобы кнопка возвращала
именно то, что играло до разговора.

Короткое срабатывает на отпускании, поэтому отклик позже примерно на
длительность нажатия. На длинном короткое действие не выполняется: ждём
отпускание и выбираем одно из двух.

Когда Алиса заговорила сама, а музыка MA ещё доигрывает буфер, хаб шлёт
`sendspin_pause` — пауза только нашего `aplay`, без касания натива.

Параметр `dialog.ma_confirm` (3 с) — сколько держать намерение, пока MA
подтверждает `pause`/`play`. MA применяет команду за 2-3 с; без этого окна
быстрый повторный клик видел старое состояние и дважды ставил паузу.

## Протокол

- Клиент сам открывает `ws://<MA>:8927/sendspin`; mDNS не используется, порт
  5353 на колонке занят `maind --platformd`.
- `client/init` → `server/init` → Noise `KKpsk2` (клиент — responder,
  Sentinel PSK) → `client/hello`.
- Роль только `player@v1`; формат только PCM 48000/16/2. MA отдаёт готовый
  PCM, декодер в агенте не нужен.
- `server/activate` приходит не при подключении, а при старте
  воспроизведения. До активации конверты всё равно обрабатываются, чтобы не
  потерять ранний `stream/start`.
- `client/state` держит `available: true`: это участие в группе, а не факт
  звука. `available: false` на паузе MA воспринимает как уход из группы.
- Аудиочанк: 13-байтовый заголовок (big-endian timestamp) + PCM; запись в
  `aplay` планируется по времени, опоздавшие чанки отбрасываются.
- Один мьютекс на `Encrypt + WriteMessage`; ping и read deadline обязательны.

## Диагностика

На колонке:

```sh
ps | grep 'aplay -q -D default'
tail -f /tmp/hermes-agent.log
```

В логе агента должны быть:

```
ws: sendspin config получен: url=… name=…
sendspin: Noise OK, server=…
sendspin: server/activate
sendspin: aplay запущен
```

При паузе — `sendspin: aplay остановлен`, процесса `aplay` нет. После
возврата — снова `aplay запущен`.

В MA:

```sh
# список плееров; ищите имя вида «Кухня (Hermes)», а не ys_...
```

Плеер должен быть `available: true`; при воспроизведении — `playing`.
Состояние и очередь удобнее смотреть через `ma_list_players` / `ma_queue`,
чем через REST `/api/players` (там другой путь и бывает пустой ответ).

## Ограничения

- Только PCM 48/16/2; FLAC/Opus не поддерживаются.
- Только unpaired/Sentinel PSK; полноценный pairing не реализован.
- `seek` задаётся абсолютной позицией; относительное «назад на N» требует
  текущей позиции из очереди MA.
- Мультирум и группы Sendspin не проверялись.
- При длинной паузе MA продолжает держать поток; локальный `aplay` его
  отбрасывает. Для TTS это нормально, для долгой паузы позиция может
  отличаться от идеальной.
