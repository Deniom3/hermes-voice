# Протокол хаба

Одно WebSocket-соединение на клиента: `ws://<хост>:8796/ws`. По нему идут и звук, и команды —
второго канала нет. Клиент обязан первым сообщением прислать `hello`, иначе хаб не знает,
кто это и с какими параметрами работать.

## Клиент → хаб

**`hello`** — первое текстовое сообщение.

```json
{"t":"hello","name":"lite-1","role":"station","threshold":0.95,
 "gain":10.0,"agc":true,"write_audio":true}
```

| Поле | Смысл |
|---|---|
| `name` | имя клиента; по нему хаб различает подключения и адресует команды |
| `role` | `station` (колонка) или `panel` (браузер) |
| `threshold` | порог ключевого слова |
| `gain` | усиление перед детектором (у колонки 10, у панели 1) |
| `agc` | применять автоматическую регулировку громкости |
| `write_audio` | писать ли поток в `/tmp/station-hub` для разбора |

**Бинарные кадры** — микрофон: PCM, 16 кГц, моно, знаковый 16 бит, little-endian. Размер
кадра произвольный; хаб режет его сам.

**`interrupt`** — прервать текущий ответ.

```json
{"t":"interrupt"}
```

**`cmd_result`** — подтверждение команды устройству (см. ниже).

```json
{"t":"cmd_result","id":"c3","ok":true,"err":null,"was_playing":true}
```

`was_playing` приходит только на `pause` и говорит, играла ли музыка до паузы. Хаб
запоминает это и шлёт `play` только если было что возвращать.

**`ping`** / **`text`** — проверка связи и, для отладки, синтез текста без распознавания:
`{"t":"text","text":"Проверка связи"}`.

## Хаб → клиент

**`hello_ok`** — подтверждение регистрации: `{"t":"hello_ok","name":"lite-1"}`.

**Бинарные кадры** — звук ответа, mp3, как отдаёт синтез. Приходят сразу после команды `say`.

**`state`** — смена состояния автомата.

```json
{"t":"state","state":"collecting","origin":"wake","score":0.97}
```

Состояния: `idle`, `verifying`, `collecting`, `busy`, `dialog_wait`. `origin`: `wake`,
`dialog`, `followup`, `verify_fail` или `null`.

**`cmd`** — команда устройству; клиент обязан ответить `cmd_result` с тем же `id`.

```json
{"t":"cmd","id":"c3","cmd":"led","name":"hermes_listening"}
```

| Команда | Поля | Что делает |
|---|---|---|
| `led` | `name` | рисунок кольца: `hermes_listening`, `hermes_thinking`, `hermes_tool`, `hermes_speaking`, `hermes_error`; пустое имя — погасить |
| `sound` | `name` | короткий звук (`spotter_start`, `err_llm`, `err_tts`) |
| `pause` | — | поставить музыку на паузу; в ответе `was_playing` |
| `play` | — | вернуть музыку (клиент сам пропускает, если паузу ставил не он) |
| `say` | `volume` | приготовиться играть звук: следующий бинарный кадр — ответ |

**`turn_start` / `turn_end`** — границы хода.

```json
{"t":"turn_start","text":"Окей, Гермес. Сколько времени?"}
{"t":"turn_end","text":"Сейчас 05:33.","cancelled":false,"chunks":1}
```

**`tool`** — что делает агент. Одно событие на оба клиента: панель рисует имя в UI,
колонка переключает кольцо.

```json
{"t":"tool","type":"tool","name":"terminal","id":"abc123","state":"start"}
```

`state`: `start` (инструмент начался) или `complete`. `id` — идентификатор вызова от
агента, по нему результат вешается на свой шаг. Хаб добавляет в это же сообщение `t`
поверх поля `type`, поэтому клиент различает его как обычное событие.

**`error`** — сбой хода: `{"t":"error","what":"llm"}` или `"tts"`.

## HTTP рядом

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | кто подключён, состояние, объём принятого звука |
| POST | `/interrupt?name=<имя>` | прервать ответ у клиента (без имени — у первого) |
| POST | `/cmd?name=<имя>` | послать команду устройству, тело — как у `cmd` |

Пример:

```bash
curl -s http://127.0.0.1:8796/health
curl -s -X POST "http://127.0.0.1:8796/cmd?name=lite-1" \
     -H 'Content-Type: application/json' -d '{"cmd":"led","name":"hermes_listening"}'
```

## Правила

- Имя клиента должно быть уникальным: новое подключение с тем же именем заменяет прежнее.
- Аудио вверх можно слать непрерывно; хаб складывает кадры в очередь и обрабатывает отдельной
  задачей, поэтому подтверждения команд не блокируются обработкой звука.
- Если клиент не отвечает на `cmd` за 15–180 с, команда считается неудачной, но соединение
  не рвётся.
- Быстрая домашняя команда выполняется без озвучки: `turn_end` приходит с пустым `text`,
  `chunks=0`, и `error` не отправляется. Это не сбой, а нормальный ход без ответа.
- Обрыв фиксируется по закрытию сокета или ошибке записи; хаб закрывает файл записи и снимает
  клиента с учёта.
