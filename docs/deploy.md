# Развёртывание

## Где что лежит

| Что | Путь |
|---|---|
| исходники (репозиторий) | `/opt/hermes-voice` |
| рабочая копия серверной части | `/srv/hermes-station/server` |
| окружение Python | `/opt/hermes-voice/.venv-wake` |
| юниты systemd | `/etc/systemd/system` |
| модель ключевого слова | `/srv/kws/models/wakeword_e90e6e54.json` |
| записи для разбора | `/tmp/station-hub` |
| агент на колонке | `/data/opt/hermes-station/voice-agent` |

Сейчас прод запускается из `/srv/hermes-station/server`, а в репозитории лежат те же файлы
в `hub/`. Раскладка историческая; при обновлении копировать файлы из репозитория в рабочую
копию и сверять `diff` — расхождение означает, что правили не там.

## Сервер: хаб и панель

```bash
cd /opt/hermes-voice
git pull

# хаб
cp hub/voice_hub.py hub/voice_dialog.py \
   hub/voice_core.py hub/voice_loop.py /srv/hermes-station/server/
/opt/hermes-voice/.venv-wake/bin/python -m py_compile /srv/hermes-station/server/voice_hub.py
systemctl restart voice-hub
curl -s http://127.0.0.1:8796/health

# панель (если менялся фронтенд)
cd panel/frontend && npm ci && npm run build
systemctl restart voice-panel
```

Юниты лежат в `panel/deploy/` и `hub/deploy/`. Установка:

```bash
cp hub/deploy/voice-hub.service panel/deploy/voice-panel.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now voice-hub voice-panel
```

## MQTT-мост

Хаб публикует сущности HA (discovery) и принимает команды через тот же брокер,
что использует HA. Включается секцией `mqtt` в `hub.json` (переменные `MQTT_*`
остались как запасной путь и для отладки); пустой `mqtt.host` выключает мост целиком.

Сущности создаются на каждую колонку по её имени из `hello` (`lite-1` → `lite_1`):
`notify.hermes_<station>` (озвучить текст), `switch.hermes_<station>_music`
(состояние музыки и пауза/возврат в одном), `sensor.hermes_<station>_volume`
и `number.hermes_<station>_volume` (громкость: наблюдение и установка, шкала 0–10,
где 0 — мьют, 1–10 — ступени станции; процентов в интерфейсе нет).
Колонка может быть не одна — сущности и топики у каждой свои, отключение
станции даёт `offline`.

Топики: `<префикс>/<station>/say`, `/<station>/music/set`, `/<station>/music`,
`/<station>/volume/set`, `/<station>/volume`, `/<station>/availability`.

Громкость везде — уровни 0–10, как у Алисы: «громкость 4» — это 4 из 10,
у агента команда `volume_set` тоже принимает уровень (`level`), а применение
делает `maind`: агент шлёт нативную директиву `VolumeSet` с процентами;
«прибавь»/«тише» — на один уровень, «выключи звук» — мьют. Процентов нет ни в речи,
ни в сущностях: `number.hermes_<station>_volume` — min 0, max 10, step 1.

Громкость берётся из ALSA-микшера `Master` на самой колонке, а не из облака:
это тот же микшер, которым управляют голос Алисы и кнопки. Агент опрашивает
его раз в 2 с и сообщает хабу событием `volume`, поэтому изменение голосом
(«Алиса, громче») видно в HA с задержкой до двух секунд. На вопрос «какая громкость»
агент читает микшер заново при каждом запросе — кэш хаба тут не приоритет.

### Уровни и дБ

Уровень 1–10 — это не «процент ALSA». У разных моделей проценты при одном и том же
уровне разные, а физическая громкость (дБ) — одинаковая. Замеры на двух колонках
(`volume_level` — то, что получает Алиса через HA):

| Алиса | Лайт 1 raw/%/дБ | Лайт 2 raw/%/дБ |
|---|---|---|
| 0.1 | 26 / 10% / −45.8 | 60 / 24% / −45.9 |
| 0.2 | 51 / 20% / −40.8 | 82 / 32% / −40.7 |
| 0.3 | 77 / 30% / −35.6 | 103 / 40% / −35.8 |
| 0.4 | 102 / 40% / −30.6 | 125 / 49% / −30.6 |
| 0.5 | 128 / 50% / −25.4 | 147 / 58% / −25.4 |
| 0.6 | 153 / 60% / −20.4 | 168 / 66% / −20.5 |
| 0.7 | 179 / 70% / −15.2 | 190 / 75% / −15.3 |
| 0.8 | 204 / 80% / −10.2 | 212 / 83% / −10.1 |
| 0.9 | 230 / 90% / −5.0 | 233 / 91% / −5.2 |
| 1.0 | 255 / 100% / 0 | 255 / 100% / 0 |

Таблица нужна только как справка. Записи в микшер агент не делает и `VOICE_VOL_TABLE`
не читает: уровень применяет `maind` по своей кривой модели, а обратно в уровень
агент переводит по дБ — `round((дБ + 50) / 5)`, 0 при нулевом проценте. Поэтому
на Лайт 2 уровень 5 и виден как 58%, а не 50%: это одна и та же громкость.

### Синхронизация громкости с облаком

Отдельного шага «сообщить HA» больше нет. Агент ставит уровень нативной
директивой `VolumeSet` в `maind` (см. `station-processes.md`), и `maind` сам
сообщает новое значение в облако — HA видит его через свою интеграцию за
~0.5 с. Проверено на Лайт 1: изменение через IPC без участия хаба обновило
`media_player.yandex_station_lite` за 0.56 с.

Раньше хаб после каждой установки слал `media_player.volume_set` с `level/10`,
потому что запись в `amixer` облако не обновляла. С появлением нативного пути
этот обход стал лишним: он дублировал команду и мог спорить с `maind`.
Секция `stations` в `hub.json` и `stations.json` тоже больше не читаются.

### Диагностика маршрута

`POST /route {"text": "Окей, Гермес, прибавь.", "station": "lite-1"}` — прогоняет фразу
через быстрый дом и возвращает `answer`, `kind`, распознанный `norm`, найденную сущность
и уровень из агента. Нужен, чтобы отвечать на «почему фраза ушла в LLM» фактом.
Маршрут **выполняет команду по-настоящему** и доступен только с `127.0.0.1`.

Озвучка из автоматизации: `notify.send_message` на нужную `notify.hermes_<station>`.
Фразы идут через очередь: `normal` ждёт, пока Гермес не закончит диалог,
`alarm` играет сразу. Дубль того же текста в течение 60 с отбрасывается.

## Правила активации

Жёсткие правила голосового контура — в [wake-rules.md](wake-rules.md). Коротко:

- перед активацией проверяются предшествующие записи: снимок кольца 6 с и
  ретро-скан с порогом 0.55; если ключ звучал раньше текущего пика, снимок
  целиком уходит в ASR (`core.prefix = snap + prefix`);
- промах 0.80–0.95 с подтверждённым обращением — это команда, а не только
  запись в датасет: окно передаётся в `SpeechCore.process_miss()`;
- порог 0.95 без замера не понижается; повтор в окне не выполняется дважды;
- фраза-триггер попадает в `intents` только после перевода её автоматизации
  на MQTT-триггер.

## Единый конфиг хаба

Все настройки живут в `/etc/hermes-voice/hub.json`; шаблон со значениями —
`hub/config.example.json`. Секреты (`HASS_TOKEN`, `MQTT_PASSWORD`) в JSON не
пишутся: они остаются в `/etc/hermes-voice/ha.env`.

Секции: `stations`, `wake`, `asr`, `tts`, `dialog`, `mqtt`, `fillers`,
`match`, `intents`.

Главное — `intents`: фразы-триггеры. Фраза, начатая ключевым словом и
совпавшая с реестром (с допуском на ошибки ASR), публикуется в
`hermes/stations/<колонка>/phrase` как `{"text": "<каноническая фраза>"}` и
**не уходит в LLM** — иначе сцена HA и агент сработали бы дважды. Не
совпала — идёт в LLM как обычный запрос.

```json
"intents": {
  "Спокойной ночи": {
    "phrases": ["Спокойной ночи", "Я спать", "Спать"],
    "anchors": ["ноч", "спат"]
  },
  "Да": { "phrases": ["Да"], "anchors": [], "mqtt": false }
}
```

`phrases` — варианты, `anchors` — корни для сильно искажённого ASR (работают
только на короткой фразе), `mqtt: false` — не публиковать («Да»/«Нет» —
подтверждение в диалоге, а не сценарий).

⚠️ Фразу добавляют в `intents` только после того, как её автоматизация в HA
слушает MQTT-топик. Иначе хаб перехватит фразу, не отдаст её в LLM, а HA её
не увидит — команда потеряется молча. Сейчас так подключена только
«Спокойной ночи»; «Вода в чайнике» и «Обычный свет» идут прежним путём
(быстрый маршрут хаба).

Файл перечитывается по `mtime`: правка фраз применяется без рестарта.
Битый JSON хаб не роняет — остаётся прошлый удачный снимок, ошибка в журнале.

Окружение переопределяет конфиг как `HUB_<СЕКЦИЯ>_<КЛЮЧ>` (`HUB_MQTT_PREFIX`,
`HUB_WAKE_THRESHOLD`) — только для разовой отладки.

## Переменные хаба (старый способ)

Исторические переменные поддержаны как запасной вариант: пока в `hub.json` нет
ключа, значение берётся отсюда. Постоянные настройки переносим в JSON.

- `ASR_URL`, `TTS_URL` — запасной путь для адресов речевого шлюза. **По умолчанию
  локальные (`127.0.0.1:8000`).** Если шлюз на другой машине — задайте `asr.url` и
  `tts.url` в `hub.json`: значения из файла приоритетнее переменных. Переменные
  оставлены для разовой отладки.
- `HERMES_WS_URL` — необязательное переопределение адреса Hermes; основной
  адрес лежит в `hub.json` → `hermes.url`.
- `HERMES_DASH_TOKEN_FILE` — файл с токеном агента Hermes.
- `HASS_URL`, `HASS_TOKEN` — Home Assistant для быстрого дома; без них модуль выключен.
- Комната колонки — `wake.stations.<имя>.area` в `hub.json`, значение из реестра HA
  (`spalnia`, `kukhnia`, `koridor`, `ulitsa`). По ней «включи свет» без названия комнаты
  относится к комнате, где стоит колонка, и «какая температура» берёт датчик оттуда же.
  Если значения нет — комната не подставляется; если такого `area_id` нет в HA —
  предупреждение `нет в реестре HA — комната не применяется` и команда идёт общим путём.
- `replies.no_area` — что сказать, если у колонки не задана `area`, а команду без
  комнаты выполнить нельзя (подходящие устройства нашлись в двух разных комнатах).
  Текст переопределяется в `hub.json`; вместо молчания и двадцати секунд ожидания
  агента станция отвечает «Комната не задана. Уточните, где именно, или настройте колонку.»
- `VOICE_FILLERS=1` — фразы-заполнители в тишине («секунду, думаю»), пока агент не начал
  отвечать. Пока не отлажены на живом разговоре, оставляем выключенными. Тайминги и предел
  числа фраз — в `hub.json → fillers` (`first_s`, `min_gap_s`, `max_gap_s`, `max_count`),
  каталог записей — `replies.dir`, кэш синтеза — `replies.cache`. Кэш чистится сам:
  при записи вытесняются старейшие файлы сверх `replies.cache_max_files` (500)
  и `replies.cache_max_mb` (50).
- `VOICE_RESUME_DELAY` — через сколько секунд после IDLE возвращать музыку на колонку
  (по умолчанию 3). Меньше — музыка влезает в микрофон, пока человек говорит фразу после
  «окей, Гермес»; больше — долгая пауза после разговора.
- `KWS_TRAIN=0` — выключить запись окон событий (по умолчанию запись включена).
- `KWS_TRAIN_DIR` — каталог живого слоя данных обучения (по умолчанию `/srv/kws/train`),
  внутри `positives`, `negatives`, `unclear` и `versions` (замороженные снимки).
- `KWS_MODEL_JSON` — путь к модели ключевого слова (в репозиторий не копируется).
- `VOICE_DUMP_STREAM=1` — писать полный поток соединения на диск для разбора (много места).

## Переменные панели

У панели свои, только транспортные — голосовой тракт целиком живёт в хабе:

- `VOICE_PORT` — порт панели (8792);
- `VOICE_HUB_URL` — хаб, к которому она подключается (`ws://127.0.0.1:8796/ws`);
- `VOICE_CDP_URL`, `VOICE_VNC_HTTP`, `VOICE_VNC_WS` — окно живого браузера и трансляция стола.

## Колонка: агент

Сборка под armhf (колонка — 32-битный ARM):

```bash
cd /opt/hermes-voice/agent
GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0 \
  go build -trimpath -ldflags="-s -w" -o voice-agent .
```

**Зависимости — из `agent/vendor`.** Раннер CI и часть сетей не достают
`proxy.golang.org` (соединение рвётся на скачивании архива), поэтому
зависимости Sendspin (`github.com/flynn/noise`, `golang.org/x/crypto`,
`golang.org/x/sys`) лежат в репозитории. Каталог не удалять: без него
`go build` уйдёт в сеть и упадёт. Обновление зависимостей — `go mod tidy`
и `go mod vendor` с машины, где прокси доступен.

Заливка и запуск:

```bash
ssh -p 2222 root@<station-host> 'cat > /data/opt/hermes-station/voice-agent.new' < voice-agent
ssh -p 2222 root@<station-host> \
  'chmod +x /data/opt/hermes-station/voice-agent.new
   mv /data/opt/hermes-station/voice-agent.new /data/opt/hermes-station/voice-agent
   /etc/init.d/S99zhermes restart
   tail -5 /tmp/hermes-agent.log'
```

В логе должны появиться строки `ws: подключено к ws://…` и `сервер принял hello`. В `health`
хаба — клиент с нужным именем и растущий `audio_mb`.

Параметры запуска задаются в `/etc/init.d/S99zhermes`. Копии — в репозитории:
`agent/deploy/S99zhermes` (Лайт 1) и `agent/deploy/S99zhermes.lite2` (Лайт 2,
отличается путями и `-mic-socket`). Скрипты совпадают с тем, что лежит на
колонках; правишь один — переноси в репозиторий, иначе версии разойдутся:

```
-server "ws://<hub-host>:8796/ws" -v
```

Порог и усиление — **параметры хаба**, а не агента: детектор работает в хабе
(`LocalWakeGate` получает PCM с колонки), поэтому колонка их больше не передаёт.
Значения живут в `/etc/hermes-voice/hub.json`, с переопределением по станции:

```json
"wake": {
  "threshold": 0.95,
  "gain": 10.0,
  "stations": { "lite-2": { "threshold": 0.95, "gain": 10.0 } }
}
```

`wake.stations.<имя>` главнее общего ключа. Если старый агент всё ещё присылает
свои `threshold`/`gain` в `hello`, хаб пишет предупреждение и применяет значение
файла — расхождение видно в журнале, но поведение задаёт конфиг.

`agent.env` на колонке не нужен вовсе:

- **адрес хаба** агент находит сам: шлёт UDP-broadcast `HERMES-HUB?` на порт
  `8797`, хаб отвечает `HERMES-HUB <ip> <port>` и агент подключается к этому
  адресу; при каждом переподключении поиск повторяется, поэтому смена IP
  хаба ничего не ломает;
- **имя станции** — по MAC: агент присылает `mac` в `hello`, хаб находит его
  в `wake.stations.<имя>.mac` и берёт имя оттуда.

Sendspin тоже настраивается на хабе, а не на колонке: URL/output — в
`sendspin`, имя и `state_dir` — в `wake.stations.<имя>.sendspin`. Агент получает
конфиг сообщением `sendspin` после `hello_ok`. Полная схема, команды управления
и диагностика — в [sendspin.md](sendspin.md).

```json
"wake": {
  "stations": {
    "lite-1": { "mac": "aa:bb:cc:dd:ee:01", "threshold": 0.95 },
    "lite-2": { "mac": "aa:bb:cc:dd:ee:02", "threshold": 0.95 }
  }
}
```

MAC можно писать в любом регистре и через `-`, `:` или `.` — нормализуется.
Станция без записи в `wake.stations` подключится под именем `mac-XXXXXXXX`
с общими порогами, и хаб напишет предупреждение.

Запуск: `voice-agent -v` — без `-server`, `-threshold`, `-gain`.
Флаг `-server` остался для ручной проверки: если задать его, поиск
выключается и используется указанный адрес. Имя колонки агент не передаёт:
хаб определяет её по MAC.

Почему не mDNS: на колонках нет `avahi` и `nss-mdns` (`getent` тоже нет), а
агент собран с `CGO_ENABLED=0` — его встроенный резолвер умеет только обычный
DNS из `/etc/resolv.conf`, имена `.local` он не разрешает. Broadcast работает
и проверен на обеих колонках.

## Модели

Распознавание и синтез живут на <speech-host> и доступны **через один шлюз на :8000**
(он же `/v1/models`). Порты `:8010` (audio.cpp) и `:8011` (silero-tts) — внутренние,
клиенты на них не ходят. Если шлюз не ответил, хаб пишет в журнал
`ASR: шлюз … не ответил (…), попытка N из 2` — по этой строке и разбирать.

```bash
curl -s http://<speech-host>:8000/health
curl -s http://<speech-host>:8000/v1/models        # какие модели видит шлюз
```

Обновление модели ключевого слова: заменить файлы в `/srv/kws/models/` и перезапустить
`voice-hub`. Путь берётся из переменной `KWS_MODEL_JSON`, копию в репозиторий не кладём.

## Проверка после обновления

1. `curl -s http://127.0.0.1:8796/health` — клиент подключён, состояние `idle`.
2. Сказать «Окей, Гермес, сколько времени» — в журнале должна пройти цепочка
   `активация → ключ подтверждён → фраза → ответ → первый звук`.
3. Проверить тайминги: сбор фразы 2–4 с, распознавание до 0.5 с, ответ агента 3–12 с,
   синтез до 0.5 с.

## Откат

- **Хаб**: `git revert <коммит>` или вернуть прошлую версию файлов в рабочую копию и
  `systemctl restart voice-hub`.
- **Агент**: собрать из предыдущего коммита и залить тем же способом. Старый бинарь хранить
  не обязательно — сборка воспроизводима из репозитория.
